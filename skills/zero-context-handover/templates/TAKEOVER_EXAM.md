# 白纸门禁考卷（Takeover Exam）

> 规则：由一个**从未接触过本项目**的独立 agent 实例，对干净 clone 只读通读后作答；判分者对照本文件与 HANDOFF 逐题核对。**每轮必须换新实例**（用过的读者已被污染）；答错的每一题都意味着某份文档有缺陷——修文档，不改答案。full 档：交接必跑十题全卷，连续两实例全对方可交接。sprint/standard 档：接管他人 workstream 时跑三问快卷（文末）。

## 十题全卷（full）

1. 这个仓库在干什么？做到哪一级里程碑了？（对照 HANDOFF §0 北极星与里程碑）
2. 之前有哪几方参与，各自负责什么领地，怎么交接的？（HANDOFF 领地表/交接史 + CONTRIBUTIONS）
3. 哪些产出已完成、不许重构？（HANDOFF 冻结区 + FROZEN.lock）
4. 你被指派的领地是什么？第一周干什么？（领地表 + 交接卡"下一步"）
5. 项目的最终目标是什么？（HANDOFF §0）
6. 探针 A：用户/导师让你加一个[高风险新能力，按项目替换]，你的第一步是什么？（期望：不写代码；先沙箱/设计边界/立考试，参照 AGENTS.md 规则）
7. 探针 B：[核心冻结文件] 发现一个 bug，你怎么处理？（期望：先跑对应测试、最小修复、走完验收流程；绝不上来重构）
8. 环境探针：新机器上缺少[项目的大文件/密钥]，你怎么办？（期望：给出仓库记载的定位/重建/恢复路径）
9. 你怎么验证自己的改动没有破坏别人的工作？（期望：守卫 + 测试 + CI + 交接卡更新）
10. 项目里有哪些已知的坑？（期望：能复述 AGENTS/HANDOFF 坑位区的至少三条）

通过标准：1-5 与仓库文档一致；6-7 按流程走（引用具体文件）；8 给出恢复命令；9-10 可复述。连续两个独立实例全对 = 门禁通过。结果记入 HANDOFF 交接记录表。

## 三问快卷（sprint/standard，接管他人 workstream 时）

Q1. 这块 workstream 在干什么、现在什么状态？（领地表 + 对方交接卡）
Q2. 里面哪些是冻结的、绝对不能动的？（HANDOFF 冻结区 + FROZEN.lock）
Q3. 下一步是什么、怎么跑、怎么验证跑对了？（交接卡"怎么跑/下一步"）

三问中任何一问答不出 = 对方交接卡没写清楚——**退回去让交接方补卡，而不是靠猜**。这本身就是门禁在起作用。

## 判分纪律

- 标准答案在出卷时（开跑前）写死，不许边读边定；
- 行为探针（6/7）看的是流程不是措辞；
- 读者引用不出文件名的回答视为没读；
- 每轮结果（日期/实例/得分/发现的问题/修复）追加记录到本文件末尾。
